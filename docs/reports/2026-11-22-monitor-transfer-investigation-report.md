# 2026-11-22 モニター間移動 — 調査報告

Issue #551。既存のCtrl+W、planner、host adapterを調査し、表示しない専用ウィンドウで
DPIと移動APIを測定した。製品コード・キー割当・設定・通常アプリは変更していない。

4台のモニター間の36条件で、移動APIが戻るまでにネイティブの位置・サイズ・DPIが
変わった。移動後に読み直した物理サイズを収める追加24条件は、すべて移動先の
work area内に収まった。ただし20条件ではXAMLの倍率がその時点で古く、さらに
大きいウィンドウでは一時的に隣のモニターへ所属する例があった。単純な倍率計算や
列挙順に頼る実装を避けるための具体的な反例を得た。

両プロセスはexit0。表示・アクティブ化はなく、観測した前面ウィンドウは維持された。
固定SDKの診断ビルドは警告0/エラー0。初回ログの「XamlRootなし」という説明は、
実データがすべてありを示していたので原本を保持して訂正した。中間ビルドも含め、
[品質記録](../quality/2026-11-22-monitor-transfer-investigation.md)に全試行を残した。

[設計資料](../design/2026-11-22-monitor-transfer-investigation.md)は提案段階。
Ctrl+W内での前後巡回、モニター順、最大化時の既存拒否、二段階の再読込または
明示的な倍率読取境界という選択肢と必要な証明を整理した。新しいADRはまだ受理していない。
実画面・キー・フォーカス・最大化の移送・切断再接続の確認は未実施。

この資料はローカル保存のみ。先行するソース公開とClaude送信の自動承認拒否は
解消していないため、外部公開・相談を再試行しない。未完了なので専用worktreeと
診断出力を保持する。[引き継ぎ](../handoffs/2026-11-22-monitor-transfer-handoff.md)に再開点を記載。

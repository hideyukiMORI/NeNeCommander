# Daily report — transfer conflict resolver — 2026-09-06

Status: Draft implementation checkpoint

Issue #73 adds typed Windows-local transfer conflicts to the existing `FileOperationGateway` path. `TransferPreflightOutcome` is closed over success, rejection, and `ConflictSet`; every source is inspected and the complete provider plan is validated before the first effect. The operation-owned continuation retains the original request, frozen source snapshots, and issued pending conflicts. It is a non-record, one-shot capability bound to its issuing gateway, so a caller cannot replace a conflict set, clone the token, resume it through another gateway, or replay it after cancellation or completion.

Skip produces no filesystem effect and is represented by `FileOperationOutcome.NotTransferred` plus ordinary processed-count progress. KeepBoth reserves a provider-comparison-aware name for the batch, uses that exact candidate for copy and verification, and deletes a move source only after successful verification. A directory candidate appends the number after the complete directory name and creates a new directory; it does not merge. File candidates append the number before the final extension. The provider does not truncate invalid or overlong candidates and returns a typed failure when existing child validation rejects them.

The Windows-local adapter rejects containment, linked-directory/reparse, child-name, full-path-length, and candidate-race failures before an effect. A candidate race returns a new conflict even after Apply-to-all. The WSL adapter preserves same-distribution non-conflict transfer and cross-provider rejection, and now derives its immutable plan from the same revalidated entry instead of performing a second unguarded lookup. Live WSL copy or deletion was not run because the repository still has no executable live harness and `NENE_COMMANDER_WSL_TEST_ROOT` is unset.

The session uses one `OperationAwaitingConflict` state and resumes the same gateway. The modal starts on Cancel. A newly issued continuation refreshes the source, existing target, KeepBoth candidate, Apply-to-all off state, and Cancel focus even when the modal was already visible; repeated rendering of the same pending continuation preserves the user's current focus and checkbox state. Modal Enter is left to the currently focused native decision button, so Tab then Enter selects Skip or KeepBoth and the initial Enter selects Cancel. Space retains native button behavior, while Escape follows the canonical mapper to cancel. The UI distinguishes not transferred, copied, verified, and source-deleted counts. It uses the approved semantic shell structure and existing resources. Canvas work provides composition direction only; final styles, fonts, colors, and new design tokens are not approved or hard-coded here. Settings persistence remains Issue #74.

## Failure-first and adversarial proof

The initial contract test failed because `PreflightTransferAsync` still returned `Task<ProviderStepOutcome>`. Behavioral tests then demonstrated the missing full-batch, Skip, and frozen-identity behavior before the gateway implementation. Later controlled failure-first checks proved that a public record continuation could be cloned and resumed twice, caller-supplied conflicts could be substituted, the WSL adapter performed a second source lookup, a visible modal could retain a stale candidate, and malformed provider plans could report success without representing every frozen source.

The final tests cover late-batch collision with zero effects, Skip with zero copy/delete effects, KeepBoth copy/verify/delete order, candidate races, provider comparison and batch reservations, direct-child containment, source order and identity, malformed/partial plans and conflict sets, Apply-to-all operation scope, continuation mutation/copy resistance, issuing-gateway ownership, same-gateway lease contention without token consumption, cancellation/completion replay, WSL single revalidation, same-distribution WSL regression, and native focused-button routing for Enter/Space with canonical Escape. The button-routing test first failed because modal Enter still produced a handled `Confirm`; after the route repair, conflict-confirm Enter becomes pass-through and each button's existing Click handler remains the only typed-decision submission path.

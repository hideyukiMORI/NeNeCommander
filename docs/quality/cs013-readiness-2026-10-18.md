## Measurement definition and limits

The audit parses all 694 tracked C# files in `src` and `tests`, including internal,
nested, test fixture, interop and source-generator input declarations. It excludes
untracked/ignored generated `bin`/`obj` files and does not measure engineering-tool
sources under `eng`. The future gate decision must explicitly settle its input set;
this inventory is not an exclusion list. There are no conditional directives or
auto-generated markers in the measured tracked inputs. No parse errors occurred.

The parser is PowerShell's installed Microsoft.CodeAnalysis.CSharp **5.0.0.0**,
explicitly using C# 14 syntax. This is an offline syntax audit, not the pinned SDK's
compiler or semantic analyzer. No product build or test was performed.

- A logical line is a nonblank physical source line occupied by a syntax token
  other than a structural brace. Comments, blank lines and brace-only lines are
  excluded; braces inside string tokens are ordinary literal content. Nonblank
  lines inside multiline literals count. No statement-count metric is substituted.
- Type counting includes its declaration, attributes, members and nested types,
  while excluding the surrounding namespace and using directives. A nested type is
  also listed independently. Partial declarations are grouped by project and
  namespace/containing-type/name/generic-arity identity and summed across files.
  No measured type has multiple tracked declarations at this baseline.
- A member is a method, constructor, operator/conversion, destructor, local function
  or accessor. Its declaration count includes attributes/signature and body. The
  separate body count omits attributes/signature. Lambdas are included in the owning
  member's token lines, not listed as separate methods; expression-bodied properties
  without explicit accessors contribute to the type only. These choices require
  confirmation before gate adoption, especially large test data attributes.
- Parameter count is the explicit syntax list, including optional, `params`, `out`
  and extension receiver parameters. Synthesized record members and generated COM
  implementations are not inspected as handwritten declarations.
- Control depth is a **screening measure**, counting nested if/loop/switch/catch/
  conditional-expression syntax; an `else if` does not add an extra level. It does
  not count try/using/lock/lambda scopes. Chained ternaries therefore appear as deep
  nesting. It is not yet the accepted definition of the CS-013 nesting rule.
- **Cognitive complexity is unmeasured.** The repository does not specify its
  algorithm or language edge cases. A control-depth count cannot establish a pass
  for cognitive complexity. No zero, pass rate or complete violation count is inferred.

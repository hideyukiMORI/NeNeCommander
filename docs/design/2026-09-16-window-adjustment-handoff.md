# Window adjustment engineering handoff

Status: engineering constraints for Issue #100 under ADR-0050

Date: 2026-09-16

hide accepted direction A on 2026-09-08: a small helper at the upper centre of the window that
names the current window operation while both panes stay visible. This handoff converts that
completed design consultation into the engineering constraints selected for the first native
WinUI implementation under ADR-0050; the token table and layout values below are engineering
decisions of this change, not part of the visual acceptance. It does not claim native runtime,
UIA, high-contrast, DPI, or scheme proof. State mockups drawn on the real Direction C shell exist
as a design reference outside the repository ("NeNe Commander Window Mode" design canvas, four
artboards: mode open and idle, after one move, refused while maximized, and the helper at 2×);
they are references, not implementation assets, and this document is the sole engineering
source.

## Component inventory

The overlay contains one raised helper surface over the frozen panes and the transparent smoke
scrim the command palette already uses. Both are declared inline in `CommanderWindow.xaml`, like
the palette overlay, so that they resolve the window-scoped `KeyHintTemplate` and stay inside the
ARC-012 scheme-resource scan; their wiring lives in `Views/WindowAdjustmentView`, in the form of
`BookmarkManagerView`. The helper is ordered as:

1. a title row: a stroke icon of a window frame, the localized mode title, and the localized
   text of the most recent outcome; and
2. one row of key hints generated by `WindowAdjustmentKeyHintPresenter` from the hint groups the
   mode's dedicated binding table declares.

There is no close button, no text editor, no candidate list, no scrim button, and no tab stop
other than the focus sink described below. The helper has three visible states that differ only in
the outcome text and its tone: idle (no outcome yet), planned (the last action was decided and
handed to the window), and refused (the last action was refused with a closed reason). It has no
opening or closing animation, timer, busy state, or transient error state.

## Layout and tokens

Every value is an existing semantic resource; no new token, family, colour key, or fixed colour is
added.

| Part | Resource |
|---|---|
| helper surface | `SurfacePaneBrush`, `FocusRingBrush` border, `BorderOperationBarThickness`, `RadiusPane` |
| helper padding | `SpacingOperationBar` horizontally, `SpacingWindowOuter` vertically |
| row gap inside the helper | `SpacingWindowOuter` |
| gap between title group and outcome text | `SpacingOperationDetailGap` |
| gap between icon and title | `SpacingKeyHintGap` |
| title | `TypographyBodySize`, bold, `TextPrimaryBrush` |
| outcome text | `TypographyMonospaceFamily`, `TypographyMonospaceSize` |
| outcome tone | idle `TextSecondaryBrush`; planned `TextPrimaryBrush`; refused `StatusWarningBrush` |
| icon | `DensityOperationIconSize`, `DensityIconStrokeThickness`, `FocusRingBrush` stroke |
| key hints | the existing `KeyHintTemplate`: `BorderKeyCapThickness`, `RadiusKeyCap`, `SpacingKeyCap`, `TextKeyHintBrush`, `TextSecondaryBrush`, `SpacingKeyHintGap` between cap and label, `SpacingOperationDetailGap` between hints |
| placement | horizontally centred over the content grid; top edge two `SpacingWindowOuter` below the content top; width fits content and never exceeds the content width |
| scrim | `SmokeFillColorDefaultBrush` over all three rows, identical to the command palette overlay |

The key-hint row shows one hint per declared hint group, with the caps the table marks for
display, in declaration order: `h j k l` for move, `+` for enlarge, `-` for shrink, `m` for
maximize, `r` for restore, and `Esc` for leave. Arrow aliases and `Ctrl+W` are declared without a
displayed cap. The cap text and the action labels come from localization resources. The refused
tone is never the only carrier of a refusal: the outcome text names the reason.

## Focus, keyboard, and pointer

The helper hosts one focus sink: a focusable control without text or visible chrome that receives
programmatic focus when the mode opens and is collapsed whenever the mode is closed, so it is never
a tab stop outside the mode. It exposes the helper as one UIA element whose Name is the localized
mode title and whose HelpText is the current outcome text. `Tab` and `Shift+Tab` are consumed
inside the mode and do not move focus. Leaving the mode returns focus once to the active pane
captured at entry.

Tapping the scrim calls the same qualified leave as `Escape`; pointer input on the helper surface
does nothing and does not bubble into the scrim. The helper has no pointer targets.

## Responsive, DPI, and accessibility notes

The helper is measured in device-independent pixels and scales with the display like the rest of
the shell. The hint row is its widest row; if localized labels make it wider than the content
width at any window size, the row wraps to a second line and never clips or hides a hint. High
contrast uses the system colours through the same semantic keys the shell already maps.

Narrator reads the title, then the outcome text on every outcome change through a live-region
change on the helper element. Nothing else on the window announces window geometry.

## Out of scope for this handoff

Window placement persistence, animation of window movement, a visible outline of the target
rectangle, pointer-driven resize handles, and any new token family are not part of direction A.
